# Bash Mastery — Complete Conceptual Quiz

## Shell Basics & Navigation

- **Q01**: The shell is best described as what kind of program?
 - A command interpreter — it reads commands from the user or a script and executes them by communicating with the kernel.

- **Q02**: When you open a terminal and see a prompt, you are interacting with a shell in what mode?
 - Interactive mode — commands are entered and executed one at a time.

- **Q03**: What is the conceptual difference between an *absolute* path and a *relative* path?
 - An absolute path uniquely identifies a file from the filesystem root `/`, regardless of where you are. A relative path is interpreted starting from the current working directory.

- **Q04**: What does the `~` (tilde) character represent in bash?
 - The current user's home directory — it's expanded by the shell before the command runs.

- **Q05**: Why do hidden files in Linux start with a `.` (dot)? What actually makes them "hidden"?
 - It's purely a convention — `ls` and most tools skip files starting with `.` by default. There is no special filesystem attribute; `ls -a` shows them.

- **Q06**: What does the `man` command give you, and why is it more useful than just searching the internet?
 - `man` shows the authoritative manual page for the exact version installed on your system — flags, behaviour, and semantics are guaranteed to match what your system actually does.

- **Q07**: What is *glob expansion* (wildcards) and who actually performs it — the command or the shell?
 - The shell expands globs before the command ever runs — `rm *.txt` means the shell replaces `*.txt` with matching filenames, then passes that list to `rm`.

## Files, Directories & Permissions

- **Q08**: In Linux, what is the fundamental principle "everything is a file" really saying?
 - Devices, pipes, sockets, and processes are all represented as file descriptors — you interact with hardware (like a keyboard) the same way you read a regular file.

- **Q09**: File permissions in Linux are expressed as three groups (user, group, others). What is the conceptual reason for this three-tier model?
 - It models three natural access domains: the file's owner, members of a shared group (e.g., a project team), and everyone else — allowing fine-grained sharing without exposing files to all users.

- **Q10**: What does the execute (`x`) permission mean on a *directory* (as opposed to a file)?
 - It means you can *enter* the directory (cd into it) and access its contents. Without `x`, you can't traverse the directory even if you know the filenames inside.

- **Q11**: What is a *hard link* and how does it differ conceptually from a *symbolic (soft) link*?
 - A hard link is another directory entry pointing to the same inode (same data). A symlink is a file that contains a path string — it points to a name, not the data. Deleting the original breaks a symlink but not a hard link.

- **Q12**: What does `umask` do? If the default umask is `022`, what permissions does a newly created file get (assuming the system default is 666)?
 - umask is a *mask of permissions to remove*. 666 minus 022 = 644, so new files get `rw-r--r--`. The umask bits are subtracted (ANDed with the complement) from the default.

- **Q13**: What is an *inode* and what information does it store?
 - An inode is a data structure storing file metadata (permissions, owner, timestamps, size, data block pointers) — but NOT the filename. Filenames live in directory entries that point to inodes.

- **Q14**: Why does `rm -rf /` require `--no-preserve-root` on modern systems? What does this reveal about how `rm` works?
 - Modern `rm` has a built-in guard specifically for `/`. This reveals that `rm -rf` is recursively called per-directory — without the guard, it would delete the entire filesystem tree starting from root.

## Redirections, Pipes & File Descriptors

- **Q15**: What are the three standard file descriptors and what are their default connections?
 - fd0=stdin (keyboard by default), fd1=stdout (terminal), fd2=stderr (terminal) — every process inherits these three open file descriptors.

- **Q16**: A pipe (`|`) connects two processes. What exactly does it connect between them?
 - It connects the stdout of the left command to the stdin of the right command — via an in-kernel buffer. Both processes run concurrently; the right command consumes data as the left produces it.

- **Q17**: What is the conceptual difference between `>` and `>>`?
 - `>` opens the file with truncation (empties it first, then writes). `>>` opens with append mode (seeks to the end, preserving existing content). Both create the file if absent.

- **Q18**: In `cmd > out.txt 2>&1`, why does the order matter? What would `cmd 2>&1 > out.txt` do instead?
 - Redirections are processed left-to-right. `> out.txt 2>&1`: first stdout→file, then stderr→stdout (which is now the file) — both go to file. `2>&1 > out.txt`: first stderr→stdout (terminal), then stdout→file — stderr still goes to terminal.

- **Q19**: What is `/dev/null` and why is it useful in shell scripting?
 - A special device file that discards everything written to it and returns EOF when read. Used to silence unwanted output: `cmd 2>/dev/null` suppresses errors.

- **Q20**: What is a *here-document* (`<<EOF`) and what problem does it solve?
 - It embeds multi-line text inline in a script as stdin for a command — solving the problem of needing to pass a block of text to a command (e.g., `cat`, `ssh`, `mysql`) without creating a separate file.

- **Q21**: What is *process substitution* (`<(cmd)`) and when would you use it instead of a pipe?
 - It makes a command's output appear as a *file* (via a named pipe or /proc/fd path). Used when a command requires a filename argument, not stdin — e.g., `diff <(sort a.txt) <(sort b.txt)`.

- **Q22**: Why does a variable set inside a pipeline subshell not affect the parent shell? For example, why does `x=0; echo "1" | read x; echo $x` print `0`?
 - Each command in a pipeline runs in its own subshell (a forked child process). Variable assignments in a subshell don't propagate back to the parent. The `read x` sets x only in the subshell, which then exits.

## Variables, Quoting & Expansion

- **Q23**: Why must there be *no spaces* around `=` in bash variable assignment (`x=5`)?
 - The shell parses commands by splitting on whitespace. `x = 5` would be parsed as the command `x` with arguments `=` and `5` — a command call, not an assignment.

- **Q24**: What is the fundamental difference between single quotes `'...'` and double quotes `"..."` in bash?
 - Single quotes are completely literal — no expansion of any kind occurs inside them. Double quotes allow variable (`$var`), command (`$(cmd)`), and arithmetic expansion, but prevent word splitting and globbing.

- **Q25**: What is *word splitting* and why is `"$var"` safer than `$var`?
 - After expansion, the shell splits unquoted results on IFS characters (space, tab, newline). If `$var` = `"hello world"`, unquoted it becomes two arguments: `hello` and `world`. Quoting preserves it as one argument.

- **Q26**: What does `${var:-default}` do, and how is it different from `${var:=default}`?
 - `${var:-default}` returns "default" if var is unset/empty but does NOT assign it. `${var:=default}` returns "default" AND assigns it to var — so subsequent uses of $var also get "default".

- **Q27**: What is the difference between `$(command)` and backtick command substitution?
 - Both capture command output, but `$()` is nestable (`$(echo $(ls))`) and easier to read. Backticks require escaping backslashes in nested cases. `$()` is the modern preferred form.

- **Q28**: What does `${#var}` give you, and what does `${var:2:4}` do?
 - `${#var}` = the length (number of characters) of the string. `${var:2:4}` = a substring starting at offset 2, taking 4 characters.

- **Q29**: What does `export VAR` do that plain `VAR=value` does not?
 - `export` marks the variable for inclusion in the environment of child processes. Without export, a variable exists only in the current shell and isn't passed to subprocesses or scripts you run.

- **Q30**: What is `IFS` and what happens if you set it to a colon `:`?
 - IFS = Internal Field Separator. It determines how bash splits words after expansion. Setting `IFS=:` makes bash split on colons — e.g., `for p in $PATH` would iterate each path element since PATH uses `:` as separator.

- **Q31**: What is *brace expansion* and when is it expanded relative to other expansions?
 - Brace expansion (`{a,b,c}` or `{1..5}`) generates multiple strings and happens *first*, before variable expansion, globbing, or any other expansion — it's purely textual.

## Control Flow

- **Q32**: In bash, what is an "exit code" and why does `if` use it rather than a boolean value?
 - An exit code is the integer a process returns when it exits (0=success, non-zero=failure). `if` runs any command and checks its exit code — 0 means the condition is true. This makes `if grep ...` work naturally alongside `if [ ... ]`.

- **Q33**: What is the difference between `[ ]` and `[[ ]]` for tests in bash?
 - `[ ]` is a POSIX command (external or built-in) that uses traditional test operators. `[[ ]]` is a bash keyword with enhanced features: pattern matching with `=~` and `==`, no word-splitting on variables, logical `&&`/`||` without quoting issues.

- **Q34**: What does `&&` mean between two commands, and how is it different from a semicolon `;`?
 - `cmd1 && cmd2`: run cmd2 only if cmd1 succeeds (exit 0). `cmd1 ; cmd2`: always run both regardless of exit status. `&&` is short-circuit AND evaluation.

- **Q35**: Predict the output: `case` logic for `x=5`.
 - high

- **Q36**: What is the conceptual difference between `while` and `until` loops?
 - `while` runs as long as the condition is true (exit 0). `until` runs as long as the condition is false (non-zero exit) — it's logically `while not`.

- **Q37**: What does `break 2` do inside nested loops?
 - Breaks out of 2 levels of nesting — i.e., it exits both the inner and outer loop, not just the innermost one.

- **Q38**: What is the output of this script? `continue` logic.
 - 1 then 3 (on separate lines) — 2 is skipped by continue.

- **Q39**: What does this idiom do? `[ -f config.txt ] || { echo "Missing config"; exit 1; }` - If config.txt does not exist as a regular file, print an error and exit. The `||` (OR) runs the right side only when the left side fails — a guard pattern.

- **Q40**: What is the `select` statement in bash and what is it used for?
 - It generates a numbered interactive menu from a list and stores the user's choice in a variable — used for building simple terminal menus in scripts.

- **Q41**: What does arithmetic expansion `$(( ))` do differently from the `let` command?
 - `$(( expr ))` expands to the result value (substitution) — useful anywhere you need the number. `let` assigns to a variable and returns an exit code (non-zero if the result is 0). `$(( ))` is more composable.

- **Q42**: A script has `set -e` at the top. Inside a function, a command fails. What happens?
 - The entire script exits immediately when the command fails — `set -e` applies to functions too. The exception is commands in conditions (`if cmd`, `cmd ||`, `cmd &&`) which are exempt from errexit.

## Functions & Scope

- **Q43**: How does a bash function return a *value* to the caller? What does `return 5` actually do?
 - `return N` sets only the exit code (0–255). To return a real value, the function prints it to stdout and the caller captures it with `result=$(my_func)`.

- **Q44**: What does `local` do inside a bash function? What happens if you omit it?
 - `local` scopes the variable to the function — it disappears when the function returns. Without `local`, a variable assignment inside a function modifies (or creates) a global variable, which can cause subtle bugs.

- **Q45**: Inside a bash function, what do `$1`, `$2`, `$@` refer to?
 - They refer to the function's own arguments (what was passed when the function was called), not the script's arguments.

- **Q46**: What is the difference between `"$@"` and `"$*"` when passing arguments?
 - `"$@"` expands to each argument as a separate, properly quoted word — safe for passing to other commands. `"$*"` joins all arguments into one string with IFS separator — arguments with spaces lose their boundaries.

- **Q47**: What does `source` (or `.`) do differently from running a script with `bash script.sh`?
 - `source` runs the script in the current shell process — all variable assignments, function definitions, and `cd` commands persist after it finishes. `bash script.sh` forks a new process; nothing leaks back to the parent.

- **Q48**: Can bash functions be recursive? What is the risk?
 - Yes, bash functions can call themselves. The risk is a stack overflow — bash allocates stack memory per call, and infinite (or very deep) recursion will exhaust it and crash the script.

## Text Processing

- **Q49**: What is the conceptual difference between `grep`, `sed`, and `awk`?
 - `grep` = filter lines by pattern. `sed` = stream editor — transform text (substitutions, deletions, insertions). `awk` = field-aware programming language — process structured columns, aggregations, conditionals on each record.

- **Q50**: What does `grep -v` do and what does `grep -c` do?
 - `-v` inverts the match (prints lines that do NOT match). `-c` counts the number of matching lines instead of printing them.

- **Q51**: In `sed 's/old/new/g'`, what does the `g` flag do and what happens without it?
 - `g` = replace all occurrences on each line. Without `g`, only the first occurrence per line is replaced — so a line with multiple "old" would have only the leftmost one changed.

- **Q52**: In awk, what do `NR`, `NF`, `$0`, and `$1` represent?
 - NR=current record (line) number. NF=number of fields on the current line. $0=entire current line. $1=first field (column 1). Fields split on FS (default: whitespace).

- **Q53**: What does `sort -k2 -n` do, and what does `-u` add?
 - `-k2` = sort by the 2nd whitespace-separated field. `-n` = numeric sort (so "10" comes after "9", not before). Adding `-u` removes duplicate lines after sorting.

- **Q54**: What is the difference between `uniq` and `sort -u`?
 - `uniq` only removes *adjacent* duplicate lines — so it requires sorted input to deduplicate fully. `sort -u` sorts AND deduplicates in one step, handling non-adjacent duplicates too.

- **Q55**: What does `xargs` solve that a simple pipe cannot?
 - Many commands don't read from stdin — they take arguments. `xargs` converts stdin lines into command-line arguments. Also, it batches many inputs into fewer command invocations (avoiding "argument list too long" errors with `rm *.txt`).

- **Q56**: What does `tee` do, and why is it useful in a pipeline?
 - `tee` reads stdin and writes to both stdout AND a file simultaneously — like a T-junction in a pipe. Useful to save intermediate results while the pipeline continues: `cmd | tee log.txt | next_cmd`.

## Processes & Jobs

- **Q57**: What is the difference between a process and a job in bash?
 - A process is a kernel-level running program (has a PID). A job is the shell's concept of a pipeline or command that was launched — the shell tracks jobs with job IDs (`%1`, `%2`) for use with `fg`, `bg`, `kill`.

- **Q58**: What happens when you press `Ctrl+Z` and what does `bg` then do?
 - `Ctrl+Z` sends SIGTSTP which *suspends* (pauses) the foreground process — it's still alive but not running. `bg` resumes it running in the background so the terminal is freed.

- **Q59**: What is the difference between `kill -9` and `kill -15` (or just `kill`)?
 - SIGTERM (15) is the polite signal — the process can catch it, clean up, and exit gracefully. SIGKILL (9) cannot be caught or ignored — the kernel immediately terminates the process. Always try SIGTERM first.

- **Q60**: What does `nohup cmd &` accomplish, and why are both parts needed?
 - `&` runs it in the background (non-blocking). `nohup` makes it immune to SIGHUP — the signal sent when you close the terminal. Without `nohup`, backgrounded processes die when you log out.

- **Q61**: What does `wait` do in a bash script that launches background processes?
 - `wait` blocks the script until all background child processes finish. `wait $PID` waits for a specific process. It also captures the exit code of the waited process via `$?`.

- **Q62**: What does `trap 'cleanup' EXIT INT TERM` do in a script?
 - It registers `cleanup` as a handler to run when the script exits normally (EXIT), receives Ctrl+C (INT), or is terminated (TERM) — enabling reliable cleanup (temp file removal, lock release) regardless of how the script ends.

## Scripting Patterns

- **Q63**: Why should you use `set -euo pipefail` at the top of production scripts?
 - `-e`: exit on any command failure. `-u`: error on unset variables (catches typos). `-o pipefail`: a pipeline fails if ANY command in it fails (not just the last). Together they turn silent failures into loud, debuggable errors.

- **Q64**: What is the purpose of a *lock file* pattern in bash scripts?
 - To prevent two instances of the same script from running simultaneously. The script creates a file on start and checks for it — if it exists, another instance is running. Combined with `trap`, the file is removed on exit.

- **Q65**: Why should you use `mktemp` instead of hardcoding a temp filename like `/tmp/myfile.txt`?
 - `mktemp` creates a uniquely-named temp file atomically, preventing race conditions where two script instances clash, and preventing symlink attacks where a malicious user pre-creates `/tmp/myfile.txt` pointing somewhere dangerous.

- **Q66**: What is wrong with this common pattern for reading file lines? `for line in $(cat file.txt); do` - Word splitting on `$(cat)` splits on all whitespace (spaces, tabs, newlines) — a line with spaces becomes multiple loop iterations. The correct pattern is: `while IFS= read -r line; do ... done < file.txt`.

- **Q67**: What does `shellcheck` do and why is it considered essential for bash scripting?
 - It's a static analysis tool that catches common bash bugs: unquoted variables, incorrect array usage, SC2 issues — things that silently fail at runtime. It's like a linter/compiler warning system for shell scripts.

## Advanced Bash

- **Q68**: What is the difference between an *indexed array* and an *associative array* in bash, and how do you declare each?
 - Indexed arrays use integer indices (0, 1, 2, ...): `arr=(a b c)`. Associative arrays (bash 4+) use string keys like a dictionary: `declare -A map; map[key]="value"`.

- **Q69**: What does `[[ $str =~ ^[0-9]+$ ]]` do and what makes regex matching in bash different from grep regex?
 - It tests if $str matches the ERE pattern (here: only digits). Unlike grep, the regex is unquoted — quoting the pattern in bash's `=~` makes it a literal string match. Captures go into `${BASH_REMATCH[@]}`.

- **Q70**: What is *parameter substitution for pattern removal* — what do `${var#pattern}`, `${var##pattern}`, `${var%pattern}`, and `${var%%pattern}` each do?
 - `#` removes shortest match from the front. `##` removes longest match from the front. `%` removes shortest match from the end. `%%` removes longest match from the end. E.g., if `f="path/to/file.txt"`, then `${f##*/}` = `file.txt` and `${f%.*}` = `path/to/file`.
